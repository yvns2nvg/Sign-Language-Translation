# kslx 결과 정리 (2026-09-04~05 세션)

`model/`(기존 TCN, 3000클래스 val 99.6%)의 검증 방식이 데이터 누수였다는 걸
증명하고, 누수 없는 프로토콜로 재학습해서 **처음으로 signer_out(미학습 수어자)
정확도를 확보**했다. 이 문서가 그 전체 과정과 최종 수치의 기록이다.

## 0. 요약

- 기존 99.6%는 모델 성능이 아니라 **분할 프로토콜의 산물**이다. 3D 키포인트가
  같은 take의 5개 카메라 앵글 파일에 비트 단위로 동일하게 복사돼 있어서,
  랜덤 분할에서는 val 샘플의 사본이 train에 그대로 들어간다.
  같은 조건(랜덤 분할, 2D 전용, 완전히 다른 모델/피처)에서도 **99.5%**가 재현됐다.
- 누수를 제거한 정직한 지표: **signer_out(미학습 수어자) top-1 97.8%**.
  이전 세션 문서는 "수어사가 1명뿐이라 이 숫자를 측정할 수 없다"고 명시했는데,
  AI Hub 세션을 16명분 전부 받으면서 처음으로 계산 가능해졌다.
- 정규화 코드에 있던 버그(어깨 동시 미검출 시 좌표가 최대 100만 배 폭발)를
  찾아 고쳤다 — 고치기 전에는 모든 프로토콜이 순수 확률(1/271) 수준에 멈춰 있었다.
- 학습에 증강(회전/전단/스케일/노이즈/손 결측/미러)을 넣어 **손 결측 시
  14%로 붕괴하던 정확도를 98.8%로, yaw 30도 회전 열화도 -23%p에서 -0.3%p로**
  고쳤다. 깨끗한 데이터에서는 0.5~1.2%p만 손해 본다.
- **최종 추천 체크포인트: `runs/signer_out_aug.pt`** (top-1 97.8%, 모든 강건성
  변형에서 1%p 이내 열화). 이 저장소에 포함돼 있다.

## 1. 데이터

| 항목 | 값 |
|---|---|
| 수어사(signer) | 16명 (REAL01~16) — 이전 세션은 1명(REAL02)뿐이었음 |
| 단어(class) | 271개 (WORD0001~0271, 라벨은 `kslx/data/word_labels.json`) |
| 카메라 앵글 | 5종 (F/D/L/R/U) |
| 클립 수 | 21,680 (16 × 271 × 5) |
| 키포인트 | AI Hub 라벨 JSON, OpenPose 포맷 (pose25 + hand21×2 + face70) |
| 학습 입력 레이아웃 | 89점(pose13 + hand21×2 + face34, `kslx/layout.py`) **2D만** |

3D 키포인트는 쓰지 않는다 — 아래 §2 참고.

## 2. 데이터 누수 증명 (모델 학습 없이, `kslx.leak_report`)

```
python -m kslx.leak_report --root <004.수어영상 경로> --signers 1-16 --words 1-271
```

| 확인 항목 | 결과 |
|---|---|
| 같은 take의 5앵글 3D 키포인트 완전 동일 비율 | **100%** (30개 표본, max_abs_diff=0.0) |
| random 분할 val 클립 중 train에 같은 take(다른 앵글) 존재 | **100%** |
| take_out 분할 가능 여부 | 가능 (16 수어사로 확보) |
| signer_out 분할 가능 여부 | 가능 (16 수어사로 확보) |

### 독립 재확인 (`kslx.leak_report_npz`)

팀원이 별도 코드베이스로 미리 만들어둔 3D npz 캐시(`Dataset_NPZ/*.npz`, 이
저장소와 무관하게 "기본은 3D keypoint 사용"이라고 명시된 스크립트로 생성됨)로
같은 주장을 독립적으로 재확인했다:

- 표본 take 중 **92%**가 5개 "앵글" 샘플에서 3D 좌표가 완전 동일.
- 아주 단순한 1-NN 분류기로: **random 분할 72.0%** vs **take_out 분할 0.0%**.
  같은 데이터, 같은(=거의 없는) 모델로 분할 방식만 바꿔도 72%p 차이가 난다 —
  이게 순수하게 누수만으로 생기는 격차다.

## 3. 정규화 버그 (발견 및 수정)

`kslx/normalize.py`의 `center_and_scale`이 프레임마다 어깨너비로 좌표를
나누는데, 양쪽 어깨가 동시에 미검출(OpenPose 컨벤션상 (0,0,conf=0))된
프레임에서는 스케일이 0에 붕괴했다. 원래 코드는 이때 고정 최솟값(1e-3)으로
나눠서, 그 프레임의 다른(미검출과 무관한) 관절 좌표까지 **최대 약 100만 배**
폭발시켰다. 이 상태로 학습한 첫 결과는 모든 프로토콜에서 정확히
1/271(top1)·5/271(top5) — 즉 모델이 발산해서 아무것도 못 배운 순수 확률
수치에 멈춰 있었다.

수정: 스케일이 비정상적으로 작은(<5px) 프레임은 그 클립 안에서 정상 검출된
프레임들의 **중앙값 스케일**로 대체. 추가로 최종 피처에 [-20, 20] clip을
방어선으로 넣었다.

## 4. 분할 프로토콜별 정확도 (증강 전, baseline)

```
python -m kslx.train --data data/kslx/word_271.npz \
    --protocol random take_out angle_out signer_out --epochs 100 --tag base
```

| 프로토콜 | top1 | top5 | n_train | n_val | 의미 |
|---|---|---|---|---|---|
| random | 99.5% | 99.9% | 18,428 | 3,252 | 참고용 — 100% take 누수 |
| take_out | 93.6% | 96.0% | 18,970 | 2,710 | 같은 signer/단어 조합 미학습 |
| angle_out | 96.0% | 99.6% | 13,008 | 8,672 | 시점 일반화 상한선 |
| **signer_out** | **98.5%** | 99.2% | 17,615 | 4,065 | **미학습 수어자 — 이전엔 측정 불가였던 지표** |

## 5. 강건성 평가 (증강 전) — 모델 선택은 top-1이 아니라 이걸로

```
python -m kslx.eval_robust --data data/kslx/word_271.npz \
    --ckpt runs/random_base.pt runs/take_out_base.pt runs/angle_out_base.pt runs/signer_out_base.pt \
    --protocol angle_out
```

| 변형 | random | take_out | angle_out | signer_out |
|---|---|---|---|---|
| clean | 99.9% | 99.2% | 96.0% | 98.9% |
| yaw±15° | -1.6 | -1.2 | **-11.3** | -0.8 |
| yaw±30° | -30.2 | -21.2 | **-49.6** | -23.1 |
| 회전±15° | -3.2 | -2.2 | **-9.1** | -3.6 |
| **손 결측** | **-85.4** | **-86.0** | **-81.7** | **-84.5** |
| 스케일±25% | -1.0 | -0.4 | -2.7 | -0.5 |

두 가지 발견:

1. **angle_out 모델이 각도 변형에 제일 약하다** — 학습 때 5앵글 중 F/D/R만 보고
   L/U를 아예 안 보기 때문에, 5앵글을 전부 본 다른 모델들보다 시점 변화에
   더 취약하다. angle_out top-1만 보고 모델을 고르면 정확히 틀린 선택을 하게 된다.
2. **손 결측에는 네 모델 다 동일하게 붕괴한다** (14%대) — 학습에 증강이 전혀
   없었기 때문. → §6.

## 6. 증강 추가 후 (`kslx/augment.py`)

학습 배치마다 샘플별 독립 확률로 미러/회전(±15°)/전단(±20°, yaw 근사)/
스케일(±20%)/노이즈/손 결측(21점 통째로 0)을 적용.

```
python -m kslx.train --data data/kslx/word_271.npz \
    --protocol random take_out angle_out signer_out --epochs 100 --tag aug --aug
```

### top-1 비교

| 프로토콜 | base | aug | 차이 |
|---|---|---|---|
| random | 99.5% | 99.5% | 0 |
| take_out | 93.6% | 92.4% | -1.2 |
| angle_out | 96.0% | 96.6% | +0.6 |
| signer_out | 98.5% | **97.8%** | -0.7 |

### 강건성 비교 (signer_out, angle_out)

| 변형 | signer_out base | **signer_out aug** | angle_out base | **angle_out aug** |
|---|---|---|---|---|
| clean | 98.9% | 99.5% | 96.0% | 96.6% |
| yaw±30° | 75.8% (-23.1) | **99.2% (-0.3)** | 46.4% (-49.6) | **95.4% (-1.3)** |
| 회전±15° | 95.4% (-3.6) | **99.4% (-0.1)** | 86.8% (-9.1) | **96.0% (-0.6)** |
| **손 결측** | 14.4% (-84.5) | **98.8% (-0.7)** | 14.3% (-81.7) | **92.8% (-3.9)** |
| 스케일±25% | 98.5% (-0.5) | 99.5% (+0.0) | 93.3% (-2.7) | 96.5% (-0.1) |

깨끗한 데이터에서 손실은 1%p 안팎인데, 실사용에서 흔한 변형(손 잠깐 안 보임,
카메라 각도 30도)에 대한 강건성은 극적으로 좋아졌다. **`signer_out_aug.pt`를
최종 배포 체크포인트로 추천한다** — 미학습 수어자 정확도와 강건성을 모두
만족한다.

## 7. 웹캠 실시간 검증

학습 데이터는 AI Hub 5카메라 원본(OpenPose 포맷)이고 웹캠은 MediaPipe를
쓰므로, `kslx/adapters/mediapipe_adapter.py`가 그 변환을 맡는다.

- **pose/hand 매핑**: 관절 대응이 명확해 신뢰도가 높다 (직접 인덱스 대응).
- **얼굴 34점 매핑**: MediaPipe 공식 얼굴 영역 상수(`FACEMESH_LEFT_EYE` 등,
  google-ai-edge/mediapipe 저장소에서 가져온 정확한 인덱스)에서 균등
  서브샘플링한 근사치다. 학습 시 얼굴 좌표(AI Hub dlib68 기반)와 완전히
  일치하지는 않는다 — **미검증**. 웹캠 인식이 이상하면 `--no-face`로 먼저
  비교할 것.

```bash
pip install torch opencv-python mediapipe pillow numpy

python -m kslx.realtime --ckpt runs/signer_out_aug.pt
```

조작: `SPACE` 녹화 시작/중지 → 예측(상위 5개+확률, 한글) | `R` 취소 |
`Q`/`ESC` 종료.

체크포인트(`runs/signer_out_aug.pt`)와 MediaPipe 모델 번들
(`kslx/mp_models/holistic_landmarker.task`)은 저장소에 이미 포함돼 있다 —
**클론 후 별도 다운로드 없이 바로 실행 가능하다.**
